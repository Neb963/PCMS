# Evidence-grounded lessons

The table records historical lessons, not findings that every old defect still exists. Apply the accepted v42/revision-2 resolution where older evidence proposed broader work. Later entries record observed implementation issues.

| Historical observation | Reusable lesson | Source |
|---|---|---|
| Alpha creation stranded nonexistent slugs at ownership checks; revisions changed its admission rule. | Availability, ownership, authentication and route readiness are separate facts. Require affirmative current Available before creation, not impossible negative ownership proof. Place possible-effect intent after read-only preflight; reconcile the same operation. | Audit §4 and §5; assumption review F10; design §6.3. |
| Primary UI and operational controllers diverged; broad green checks preceded operator failures. | Put each task's UI and backend in the same slice. Click the actual packaged control and inspect independent effects. Source/fixture, installed, disk and live evidence answer different questions. | Audit §4, historical N4–N6; design §§11–12. |
| Generic recovery and coarse busy flags hid safe account actions or left stale errors. | Store typed target/step/schema/recovery, show fresh per-item state, and keep unrelated safe work usable. Never make Retry a replay of an unknown mutation. | Audit §4; assumption review F20/F24. |
| A nonexistent native Finish and publish button was treated as a plausible dependency. | Name the owner and observable result of every control. AI readiness, human acceptance, save, Git write, listing, pool and DONE need distinct evidence. | Assumption review opening correction and F01–F04. |
| Unregistering a userscript was mistaken for stopping code already in an open document. | Fence capabilities immediately and require page teardown receipts before a new writer. Preserve dirty editor/chat/undo state. | Assumption review F05; design §3.3. |
| The first prompt probe trimmed before comparison and mixed character and byte lengths. Its corrected run reset its log. | Compare raw text and UTF-8 hashes separately. Keep run provenance; a fresh log cannot prove continuity of the prior run. Identical transfer fixtures do not test substantive AI interpretation. | DEVELOP assessment, Findings/Probe correction; design §1 evidence L and §7. |
| The early Firefox proof had disabled OS sandbox; later normal-sandbox lifecycle evidence superseded that limit. The API proof build was a beta. | Preserve the exact evidence environment. An API proof, valid packaged version comparison and distribution acceptance are separate claims. Environment failures do not justify weakened production protection. | Feasibility §§2/5; revision-2 correction report §2. |
| Old archive logic excluded credentials; cookies alone did not establish session restore. Earlier proposals expanded to whole AI storage and native export. | Define complete required coverage, not indiscriminate collection. Use narrow auth schemas, report incomplete sections and distinguish restored bytes from working sessions/routes. External OS setup stays an explicit prerequisite under the accepted design. | Audit §5; assumption review F08/F16/F21; design §10 supersedes older scope. |
| Raw directory data and an HTML-only save did not meet Refresher requirements. | Observe rendered filters/pins and qualify markers in both root files. Record source save and measured visibility separately; neither implies the other. | Audit §5; assumption review F14–F15; design §8. |
| Proof CI failures included missing alarm arming, non-cloneable return values and a fixture expecting session cookies to survive clean shutdown. | Inspect the failing harness oracle and lifecycle assumptions before changing product contracts. Repair the actual defect without weakening sandbox or necessary checks. | Feasibility §5, final paragraph. |

Add entries only for a real mistake, unexpected behavior or useful improvement with its evidence. At project completion, extract reusable lessons for the knowledge base without copying project-specific requirements as universal rules.

- Planning review (2026-10-31): a READY dependency must not hold the writer resource needed by its prerequisite Creator; split long lifecycle/archive tasks by independent evidence; do not make a shared Downloads service depend on a disableable module. These were planning risks corrected before implementation, not production defects.

- P01 (2026-10-31): the Mozilla checksum manifest contained rows that broke two-field unpacking. Match the exact archive path and digest field, then verify the bytes; do not skip integrity checking. Runs `41214431538` and `41214513710` show the failure and repaired download.
- P01: Firefox’s outer extension toolbar item can receive trusted mouse/command events without invoking its action button. Target its `.webextension-browser-action` child and verify the resulting tab. Run `41215127877` exposed the wrapper mistake; run `41215249127` opened the real dashboard. A click receipt alone was insufficient.
- P01: a dashboard can connect before asynchronous donor attachment. Wait for that finite startup result; otherwise a one-shot status response can leave it showing stale Starting. The focused cold-request test checks attachment and failed-bootstrap settlement.

- P01: a clean Firefox profile includes default containers. Their existence is not evidence of an old PersonaMonkey installation. Run `41215468856` exposed the overly strict profile guard. Reject existing donor authority and let the donor quarantine unmapped containers; never clear user data to pass startup.

- P01: WebDriver session creation can return while Firefox still reports add-on startup as `starting`. Run `41215955311` recorded a trusted native click but zero product icon events. Wait for Firefox’s native add-on startup state before interacting; permit a dormant event page so the test still exercises a real wake. Do not replace the required click with a handler call or direct navigation.
